# #58 command/revision matrix

| command | normalized semantic operation | one revision | evidence/history | permanent test |
|---|---|---|---|---|
| create Atom | `atom.create` + initial items | yes, sequence 1 | initial journal/checkpoint | engine + persistence |
| create item | stable/generated ReviewItemId | yes | summary/journal | engine generated identity |
| update item text | title/description | yes | journal | engine operation path |
| set result | actor-scoped evidence | yes | preserves prior actors | evidence/coordination test |
| set coordination | Desired/Effort/Owner/Work/dependencies | yes for patch | summary/history | coordination test |
| add comment | actor/comment/reply | yes | commentIds/activity | model/engine implementation; packaged e2e |
| restore | reconstruct historical whole state | new current revision | old history retained | restore test |
| replay command | receipt lookup | no second revision | receipt result replayed | idempotency test |
| stale expected revision | reject | no write | conflict | stale/concurrent tests |

Revision identity is logical and generated by Review engine; physical IndexedDB
writes may include metadata/items/journal/checkpoint/receipt. A single semantic
transaction must not be inferred from physical write count.
